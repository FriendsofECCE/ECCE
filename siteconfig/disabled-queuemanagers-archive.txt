ECCE - archived, retired queue manager definitions
==================================================

These queue managers were removed from siteconfig/QueueManagers (and, where
they had one, from siteconfig/submit.site) on 2026-09-22 because the
schedulers themselves are obsolete:

  EASY         The EASY backfilling scheduler, from the early-1990s IBM SP
               era. Long dead; had no submit.site directive block here
               either, so it could never have produced a working script.
  LoadLeveler  IBM's scheduler, discontinued; IBM's own path forward was
               Spectrum LSF, which is still supported here.
  Maui         The open-source scheduler superseded by Moab (also still
               supported here) and effectively unmaintained for over a
               decade. Its definitions below even invoke LoadLeveler's
               commands (llsubmit/llcancel/llq), which is a fair summary of
               how current they were.

Kept verbatim, not deleted, so re-enabling one is a copy-paste -- exactly
the convention data/client/config/disabled-codes-archive.txt uses for
computational codes.

Nothing in the C++ depends on these names; the only occurrences were two
comments (RefQueueMgr.C, RunMgmt.C).

Still supported, for the record: Slurm (the common case on new clusters),
PBS (OpenPBS/PBS Pro), LSF, Moab and Shell. SGE joined the retired list
later the same day -- see the second batch below.

Update 2026-09-22, after actually generating a script for each of them:
being listed in QueueManagers was never evidence that a manager WORKED.
The PBS and LSF directive blocks in submit.site were Cray NQE/NQS syntax
that no current scheduler accepts ("-lM 28Mw", "-lT 7200", the
mpp_t/p_mpp_t/mpp_p resource names, "-J m", a lowercase "-s" for the
shell, and "-r $submitFile" where PBS's -r is the restartable flag and
LSF's is rerunnable, neither being the job name). The Moab block was
empty outright, so Moab jobs carried no directives at all. All three have
been rewritten; only Slurm has been checked against a real scheduler's
documentation on this machine. If you are adding a manager, generate a
script and read it before believing the list.

From siteconfig/submit.site: LoadLeveler
==================================================================
LoadLeveler {
# @ class            = $queue
# @ wall_clock_limit = $wallTime
# @ input            = /dev/null
# @ output           = llout.out
# @ error            = llerr.out
# @ environment      = COPY_ALL; MP_EUILIB=us; MP_CSS_INTERRUPT=yes; MP_INFOLEVEL=2; MP_EUIDEVICE=css0; MP_PULSE=0; MP_SINGLE_THREAD=yes;
# @ min_processors   = $nodes
# @ max_processors   = $nodes
# @ queue
}

Second batch, 2026-09-22: SGE
==================================================================
Sun Grid Engine. Oracle discontinued it after acquiring Sun; the
surviving forks are either commercial (Altair Grid Engine) or
unmaintained (Son of Grid Engine). Kept in the first pass of this
retirement because it is still occasionally encountered, then retired
on the maintainer's decision.

From siteconfig/QueueManagers:
SGE|submitCommand:           qsub ##script##
SGE|cancelCommand:           qdel ##id##
SGE|queryJobCommand:         qstat
SGE|queryMachineCommand:     qstat -F
SGE|queryQueueCommand:       qstat -f
SGE|queryDiskUsageCommand:   df -k
SGE|jobIdParseExpression:    .*
SGE|jobIdParseLeadingText:   job 

From siteconfig/submit.site:
SGE {
#$ -pe make $totalprocs
#$ -v SHELL
#$ -cwd
}
